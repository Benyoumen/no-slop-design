# Sources

Public work this method builds on, and what it takes from each. The rules themselves are the author's; the references are where to go deeper.

- [impeccable](https://github.com/pbakaus/impeccable), open-source design skills for coding agents. Used after the content and the data are right, for craft passes on a surface (typography, color, polish, critique). The rules here decide what the screen is for; impeccable helps make it well.
- [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines), Vercel. A reviewable list of interface rules for accessibility, forms, motion and typography, run as a review pass on the generated HTML.
- [Understanding contrast (minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), W3C WCAG 2.2. The 4.5:1 and 3:1 thresholds behind every contrast measurement in the audit.
- [HAX Toolkit](https://www.microsoft.com/en-us/haxtoolkit/), Microsoft. Guidelines for human-AI interaction; what an agent screen must make visible about what the system can do and did.
- [People + AI Guidebook](https://pair.withgoogle.com/guidebook/), Google. Patterns for trust, feedback and errors in AI products; the four things an agent screen shows (presence, proposals, approval, trail) draw on it.
- [agent-design-principles](https://github.com/Benyoumen/agent-design-principles), the companion repository: the fourteen density rules for operator screens, the write contract between a control and the system of record, the autonomy tiers.
- [backlog-writing-system](https://github.com/Benyoumen/backlog-writing-system), the companion repository: where the decisions of a validation session become Features and User Stories, and where acceptance criteria for AI behavior become eval cases.
