# Visual slop audit

> Slop is the look of a screen nobody decided. The audit finds each undecided default and asks for the decision.

## When to use

- Before a mockup or a page is shown to anyone outside the team.
- When someone says a screen "looks like AI" and cannot say why.
- When reviewing a page generated by a tool from a one-line prompt.
- As the gate before a build, with the allowlist of accepted exceptions.

## Inputs

1. The screen, open in a browser, at a wide and a narrow width (for example 1280 and 390).
2. The brief, so the audit can judge copy against the job and the person.
3. The tokens in use, to check sizes and colors against the scale.
4. The allowlist from the previous audit, if any: exceptions already decided, with their reasons.

## Procedure

1. **Run the five-second test first.** Open the screen cold and answer, without scrolling: What is this for? Who is it for? What would I do first? Does it look like somebody decided? Write the four answers. A missing answer is the first finding.
2. **Sweep the sixteen tells** in [docs/visual-slop-tells.md](../../docs/visual-slop-tells.md), in order. For each: `pass`, `fail` with the evidence (where on the screen), or `accepted` with the allowlist reason.
3. **Measure** at both widths: contrast of every text pair against 4.5:1 (3:1 for text at 24px or larger), clipping of any element outside its container, left-edge alignment within 1px in each column, click targets at least 40px on the small side, keyboard reach and visible focus on every control, Escape on every dialog.
4. **Check the states.** Empty, loading, error and success exist and can be reached. Each error says what happened and what to do.
5. **Read every string.** Headline, labels, buttons, empty states. A string that could sit on another product fails tell 4 or 15.
6. **Write the verdict**: ready, ready with the listed exceptions, or not ready, and the three changes with the largest effect.
7. **Add every new finding you decide to accept** to the allowlist, with the reason and the date. Match by rule, file and location, never by a snippet of code.

## Rules

- A finding is a location and a measurement, not an opinion. "Low contrast" is not a finding; "body text on the hero measures 2.9:1 at 1280" is.
- Measured checks run at two widths. One width is not an audit.
- A tell can be accepted, never ignored. Acceptance is written with its reason.
- The allowlist holds decided exceptions, not forgotten defects. A new defect that resembles an old one is still new.
- Copy is part of the audit. Words that were not written for this person are a visual defect too, because the reader sees them before anything else.
- The verdict names the three changes with the largest effect, so the fix starts there.

## Checklist

- [ ] Five-second test written down, four answers.
- [ ] Sixteen tells, each with pass, fail plus evidence, or accepted plus reason.
- [ ] Contrast measured on every text pair, both widths.
- [ ] Clipping, alignment and targets measured, both widths.
- [ ] Keyboard path complete, focus visible, dialogs close by Escape.
- [ ] Four states reachable; errors say what happened and what to do.
- [ ] Every string read against the brief.
- [ ] Verdict with the three largest changes.
- [ ] Allowlist updated with reasons and dates.

## Example

Acme Field Sales Assistant, the generic version of the rep's daily list ([live](https://benyoumen.github.io/no-slop-design/daily-list-generic.html)).

Weak audit: "Looks generic, maybe change the colors."

Corrected audit, abbreviated: five-second test fails on "what would I do first" (the only visible button says "Get started"). Tells 1, 2, 4, 5, 6, 7, 11 and 15 fail with locations. White body text on the hero gradient measures below 4.5:1 at its lighter end. No empty, loading or error state exists. Verdict: not ready. Largest changes: replace the hero with the list of today's meetings on real data; put the agent's proposals in their own column with an approve action that names its effect; add the four states. The full sheet is in [`examples/acme-sales-assistant/audit.md`](../../examples/acme-sales-assistant/audit.md).

## Definition of done

Every tell has a verdict, every measurement has a number and a width, the states were reached, every string was read, and the verdict names the three changes with the largest effect.
